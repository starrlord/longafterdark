# Long After Dark — imported API surface

Generated by `research/win/census.py` + `research/win/api_surface.py` (gitignored, like all of `research/`) from the Windows binaries of the After Dark 4.0 Deluxe disc, in `<assets>/win/FILES` (relocation/import tables only — nothing executed). Counts are the number of binaries of the lane that import the function. Classification is a first pass: **stub** = return a constant, **passthrough** = call the real Win32 API after marshalling handles/pointers, **emulate** = implement against emulated state, **real** = resolved to another After Dark image that runs as emulated code (engine/helper DLL exports; no shim). Evidence and call sites are in `ABI.md`. **Since generation this file is maintained by hand**: the sound rows (below) were reclassified after the audio work, and regenerating it would undo that.

The classification is the plan the runtimes started from. What each runtime implements now is in `host/win32/README.md` and `host/win16/README.md`; module dialogs, which the saver still refuses, run as real dialogs in configure mode (`INTERACTION.md` §6.2). Imports that only the other releases use (10th Anniversary, After Dark 3.2, Totally Twisted, The Simpsons, and the later ones below) are not counted here; `PACKAGES.md` §7.3 and §10 name the ones they added.

Star Wars Screen Entertainment, the sixth release, is not counted here either: it is not After Dark, and its surface was censused on its own (`research/win/pkg/swse/survey/api_census.md` and `api_census.json`, gitignored: every import of the disc's 38 NE files, static and through `GetProcAddress`, against the Win16 runtime's shims, with call sites and a probe run of all 14 modules). The 22 binaries a module needs (the 14 `.IMX` files, `SWSE.DLL`, `INTRMLIB.DLL`, `ANTSW.DLL`, `READJPG.DLL`, `STRESS.DLL`, `SWSFX.DLL`, `MEMMIDI.DLL` and `IMIMXPLY.IMQ`) import 279 distinct system functions: USER 112, KERNEL 74, GDI 64, MMSYSTEM 14, COMMDLG 3, TOOLHELP 1, WIN87EM 1, and the 10 WinG entry points `SWSE.DLL` looks up by name, which its GDI path never calls. What that census found missing, and what the runtime added for it — `GetTempFileName` creating its file, `AccessResource`, the DIB driver (`CreateDC("DIB")`), resource use counts, `MulDiv`, `PaintRgn`, `CreateHatchBrush`, `CreateDIBPatternBrush`, `GetSystemPaletteUse`, `SetHandleCount`, `GlobalWire`/`GlobalUnWire`, `GetMenu`, `GetWindowTask`, `GetNextWindow`, `ChooseFont` — is in `host/win16/README.md` ("Intermission modules"); the protocol and the modules' needs are `ABI.md` §3.8. WinG, which the disc also ships, is never loaded (`PACKAGES.md` §7.5).

Star Trek: The Screen Saver, the seventh release (After Dark 2.0b), is not counted here either: its surface was checked on its own (`research/win/pkg/startrek/lane/impcheck.json` and `neinv.json`, gitignored: every import of the release's 38 NE files against the Win16 runtime's shims, and runs of all 16 modules). The 25 NE files the package installs beside `AD.EXE` (the 16 modules, `AD_MOD.DLL`, `AD_RSRC.DLL`, `AD_MME.DRV`, the five `ST_RES` DLLs and `AD_SND.DLL`) import 145 distinct system functions, GDI 61, KERNEL 50, USER 33 and WIN87EM 1, and each already had a handler (five are dialog calls made only in configure mode: `DlgDirList`, `DlgDirSelect`, `GetDlgItem`, `GetDlgItemText`, `CheckDlgButton`). `AD_MME.DRV` reaches seven MMSYSTEM functions through `GetProcAddress` by ordinal (`AUDIO.md` §2.12), and `AD_MOD.DLL` looks up `GETFREESYSTEMRESOURCES` and `GETHEAPSPACES` by name at run time. No run called an unimplemented function. What the runtime changed for the release: `GetKeyState(VK_NUMLOCK)`'s toggle bit, `[-h-]` among the drives `DlgDirList`, `LB_DIR` and `CB_DIR` list, and `StretchDIBits` and `SetDIBitsToDevice` into a memory DC holding a monochrome bitmap, which now hand real GDI the DIB's own colours, as `SetDIBits` did (`host/win16/README.md`, "After Dark 2.0").

The five releases of the twelve-release registry (Marvel Comics Screen Posters, Snoopy's Screen Savers, The Looney Tunes Screen Saver, ScreamSavers, The Disney Collection Screen Saver) are not counted here either: each survey ran every module of its release and counted the calls the runtime did not implement, and the Marvel, Looney Tunes and Disney surveys also checked every import statically against the Win16 runtime's shims (`research/win/pkg/{marvel,snoopy,looney,scream,disney}/`, their `impcheck*.json`, `neinv.json` and runs, gitignored). No row below changes, since none of these functions is imported by a binary of the Deluxe disc (so the headings' counts stand), except the note on `GetDIBits`. What the runtime added for them (`host/win16/README.md`): **GDI** `GDI.81 GetMapMode` (every ScreamSavers module copies the screen DC's mapping mode to its memory DC), `GDI.25 FloodFill` and `GDI.372 ExtFloodFill` (Snoopy's sprite masks), `GDI.49 CreateBitmapIndirect` and `GDI.60 CreatePatternBrush` (Little Mermaid's "Plain" sea), and `GetDIBits` to 4-bit rows (Haunted), with a `DIB_PAL_COLORS` table that describes the returned hardware indices (the Looney Tunes' labels) and rows of monochrome bitmaps at 1, 4, 8 and 24 bits; **KERNEL** `KERNEL.93 GetCodeHandle`, `138 GetHeapSpaces` (which `MARVEL.AD` looks up by name, as Star Trek's `AD_MOD.DLL` does), `170 AllocCStoDSAlias`, `171 AllocDStoCSAlias`, `175 AllocSelector`, `176 FreeSelector`, `186 GetSelectorBase`, `187 SetSelectorBase`, `188 GetSelectorLimit` and `189 SetSelectorLimit` (Marvel's `DECO.DLL`), and the freed-selector rule; **TOOLHELP** `TOOLHELP.51 GlobalFirst` and `52 GlobalNext`, an empty walk (the Disney Collection's music modules); and **AD_SND** as a system module of the host's own, with AD_SND 3.0.3's 36 entries, for a package that ships no `AD_SND.DLL` (Snoopy's; `AUDIO.md` §2.10, `ABI.md` §3.13). Configure mode needs nothing new: Marvel's and the Looney Tunes' dialogs use calls it already had, and `AD_SND`'s dialog-only `CheckDlgButton` and `IsDlgButtonChecked` are never reached.

Sound is the largest change since that plan. With sound on (`ADSOUND=1` or `ADAUDIOOUT`; the saver turns it on for the primary monitor's host), DirectSound, MSACM32, the WINMM MCI sequencer, `waveOut` and aux calls, and MMSYSTEM's `sndPlaySound`, `waveOut*`, `midiOut*`, `aux*` and `mciSendString` are **emulated** over the host audio engine (`AUDIO.md` §7, §8); those rows are classed `emulate` below, and their notes say what the sound-off host answers, which is exactly what the silent host of before answered. `waveIn*`, the mixer and CD audio stay without a device either way.

Lanes (what runs as emulated code):

* **pe32** — the 22 `AD40/*.AD` modules, `ENGINE/STARRYNI.AD`, and `AD40/ADXPL510.DLL` (24 binaries).
* **ne16** — the 61 `CLASSIC/*.AD` modules, the 12 Classic helper DLLs (`ADXPL300`, `ADTOOL`, `AD_RSRC`, `AD30RSDB`, `READBMP/FILE/GIF/MMP/PCX`, `DJPG`, `DTARGA`, `STOIKDTH`) and `ENGINE/OLDMOD16.DLL` + `ENGINE/AD_SND.DLL` (75 binaries).
* Not emulated (replaced by our host, listed for reference at the end): `AFTERDAR.SCR`, `AFTERDAR.EXE`, `OLDMOD32.DLL`, `ADPAGE.DLL`.
